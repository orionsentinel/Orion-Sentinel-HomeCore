# Flight Intelligence Security

## Security Architecture

Flight Intelligence follows security best practices for homelab deployments:

### 1. **Defense in Depth**
- Network isolation via Docker networks
- Non-root containers
- Secrets via environment variables
- Minimal exposed ports
- Localhost-only binding by default

### 2. **Principle of Least Privilege**
- Services run as unprivileged users
- Read-only filesystems where possible
- Limited container capabilities

### 3. **Data Protection**
- Encrypted database connections (optional)
- Secure password generation
- No secrets in code or logs

## Security Features

### Non-Root Containers

All services run as non-root users (UID 1000):

```dockerfile
# Example from Dockerfile.api
RUN useradd -m -u 1000 flightintel
USER flightintel
```

**Verify**:
```bash
docker exec flight-api whoami
# Output: flightintel (not root)
```

### Localhost-Only Binding

By default, services bind to `127.0.0.1` (localhost only):

```bash
# .env
HOST_IP=127.0.0.1
```

**Access**:
- ✅ From same machine: http://localhost:8501
- ❌ From network: Not accessible

**For LAN Access**:
```bash
# Change HOST_IP to your machine's IP
HOST_IP=192.168.1.100

# Restart services
docker compose --profile flight-intel restart
```

**Warning**: Only enable LAN access if needed and behind firewall!

### Secrets Management

Secrets are:
1. **Generated** automatically by `bootstrap.sh`
2. **Stored** in `.env` (not committed to git)
3. **Loaded** via environment variables
4. **Never hardcoded** in source code

**Generated Secrets**:
- Database password (32 chars)
- API key (32 chars)
- JWT secret (48 chars)

**Verify .env is gitignored**:
```bash
git check-ignore .env
# Output: .env
```

### API Authentication

Protected endpoints require API key:

```bash
# Trigger collection (requires key)
curl -X POST "http://localhost:8000/collect/trigger" \
  -H "X-API-Key: your_api_key"
```

**Unprotected endpoints** (read-only):
- `/health`
- `/routes`
- `/offers/best`
- `/history`
- `/recommendation`
- `/metrics`

**Protected endpoints** (write/trigger):
- `/collect/trigger` (requires X-API-Key header)

### Database Security

**Connection**:
- Host: `flight-postgres` (internal network only)
- Credentials: From environment variables
- No external access by default

**Hardening**:
```bash
# Limit database user permissions (if needed)
docker exec flight-postgres psql -U postgres -c "
REVOKE ALL ON DATABASE flightintel FROM PUBLIC;
GRANT CONNECT ON DATABASE flightintel TO flightintel;
"
```

### Container Isolation

Services use dedicated Docker network:

```yaml
networks:
  flight-internal:
    name: flight-internal
    driver: bridge
    internal: false  # Set to true for full isolation
```

**Full isolation** (no internet access for containers):
```bash
# Edit compose.yaml
networks:
  flight-internal:
    internal: true

# Rebuild
docker compose --profile flight-intel up -d
```

**Note**: This breaks Amadeus API calls. Use for air-gapped setups only.

## Security Checklist

### Initial Setup

- [ ] Run `bootstrap.sh` to generate secure secrets
- [ ] Review `.env` and change default values if needed
- [ ] Verify `.env` is not committed: `git status`
- [ ] Set `HOST_IP=127.0.0.1` unless LAN access needed
- [ ] Set strong `API_KEY` (auto-generated by bootstrap)

### Production Deployment

- [ ] Change all default passwords
- [ ] Enable firewall on host
- [ ] Restrict Docker daemon access
- [ ] Use TLS for external access (via reverse proxy)
- [ ] Enable audit logging if required
- [ ] Regular security updates: `docker compose pull && docker compose up -d`

### Ongoing Maintenance

- [ ] Rotate secrets every 90 days
- [ ] Review access logs regularly
- [ ] Keep Docker images updated
- [ ] Monitor for CVEs
- [ ] Backup encryption keys

## Threat Model

### Threats Addressed

✅ **Unauthorized API Access**
- Mitigation: API key authentication on sensitive endpoints

✅ **Container Escape**
- Mitigation: Non-root users, limited capabilities

✅ **Data Exposure**
- Mitigation: Localhost-only binding, Docker network isolation

✅ **Credential Theft**
- Mitigation: Secrets via env vars, not committed to git

✅ **SQL Injection**
- Mitigation: SQLAlchemy ORM with parameterized queries

### Threats NOT Addressed

⚠️ **Physical Access**
- Mitigation: Secure physical access to server

⚠️ **Host Compromise**
- Mitigation: Harden host OS, regular updates, firewall

⚠️ **DDoS**
- Mitigation: Rate limiting at reverse proxy level (not included)

⚠️ **Advanced Persistent Threats**
- Mitigation: This is a homelab system, not designed for high-security environments

## Secrets Rotation

### Rotate API Key

```bash
# Generate new key
NEW_KEY=$(openssl rand -base64 32 | tr -d '=/+' | head -c 32)

# Update .env
sed -i "s/API_KEY=.*/API_KEY=$NEW_KEY/" .env

# Restart services
docker compose --profile flight-intel restart

# Update any scripts/clients using the old key
```

### Rotate Database Password

```bash
# Generate new password
NEW_PASS=$(openssl rand -base64 32 | tr -d '=/+' | head -c 32)

# Update database
docker exec flight-postgres psql -U flightintel -c "
ALTER USER flightintel WITH PASSWORD '$NEW_PASS';"

# Update .env
sed -i "s/POSTGRES_PASSWORD=.*/POSTGRES_PASSWORD=$NEW_PASS/" .env
sed -i "s/:.*@/:$NEW_PASS@/g" .env

# Restart all services
docker compose --profile flight-intel down
docker compose --profile flight-intel up -d
```

### Rotate JWT Secret

```bash
# Generate new secret
NEW_SECRET=$(openssl rand -base64 48 | tr -d '=/+')

# Update .env
sed -i "s/JWT_SECRET=.*/JWT_SECRET=$NEW_SECRET/" .env

# Restart services
docker compose --profile flight-intel restart
```

## Secure Access Patterns

### Reverse Proxy (Recommended for External Access)

Instead of exposing ports directly, use a reverse proxy:

```nginx
# nginx example
server {
    listen 443 ssl http2;
    server_name flights.yourdomain.com;

    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    # UI
    location / {
        proxy_pass http://127.0.0.1:8501;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # API
    location /api/ {
        proxy_pass http://127.0.0.1:8000/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### VPN Access

For remote access, use VPN instead of exposing ports:

1. Set up WireGuard/OpenVPN on your homelab
2. Keep `HOST_IP=127.0.0.1`
3. Access via VPN tunnel

## Vulnerability Management

### Regular Updates

```bash
# Update base images
docker compose --profile flight-intel pull

# Rebuild containers
docker compose --profile flight-intel build --pull

# Restart
docker compose --profile flight-intel up -d
```

### Security Scanning

Scan images for vulnerabilities:

```bash
# Install Trivy
brew install trivy  # or apt-get install trivy

# Scan image
docker compose build flight-api
trivy image flight-intel-flight-api

# Scan for critical and high severity only
trivy image --severity CRITICAL,HIGH flight-intel-flight-api
```

### Dependency Updates

```bash
# Check for outdated Python packages
cd stacks/flight-intel
pip list --outdated

# Update specific package
uv pip install --system --upgrade sqlalchemy

# Update all
uv pip install --system --upgrade-package "*"
```

## Incident Response

### Suspected Breach

1. **Isolate**:
   ```bash
   docker compose --profile flight-intel down
   ```

2. **Investigate**:
   ```bash
   # Check logs
   docker compose logs > /tmp/incident-logs.txt

   # Check for unauthorized access
   grep "401\|403" /tmp/incident-logs.txt

   # Check database connections
   docker exec flight-postgres psql -U flightintel -c "
   SELECT * FROM pg_stat_activity;"
   ```

3. **Rotate All Secrets**:
   ```bash
   # Run rotation scripts (see above)
   ```

4. **Review**:
   - Check for unauthorized API calls
   - Review database changes
   - Scan for malware
   - Update and restart

### Logs Review

```bash
# API access logs
docker compose logs flight-api | grep "GET\|POST"

# Failed authentication attempts
docker compose logs flight-api | grep "401"

# Database errors
docker compose logs flight-postgres | grep "ERROR"

# Collection errors
docker compose logs flight-collector | grep "ERROR\|WARN"
```
